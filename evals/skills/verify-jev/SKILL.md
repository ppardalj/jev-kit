---
name: verify-jev
description: Decide which ./scripts/verify suites a change in el-baul needs, by having Jev score every suite against the diff and docs/architecture/testing.md. Use when asked which tests or verify suites to run for the current changes or for a commit.
argument-hint: "[commit or range; default: uncommitted changes]"
---

Jev, through the `ask_jev` tool, reads the diff and the testing doc for you and scores how much each suite is needed, in one call. The diff never enters your context.

1. **Write the diff to a file** in one Bash call. `.run/` is gitignored. The file starts with the list of changed paths, then the diff.
   - No argument, the uncommitted changes, untracked files included:
     `mkdir -p .run && { git diff --name-status HEAD; git ls-files -o --exclude-standard | sed 's/^/A\t/'; echo; git diff HEAD; git ls-files -o --exclude-standard -z | xargs -0 -r -n1 git diff --no-index /dev/null; } > .run/verify-jev.diff; wc -c .run/verify-jev.diff`
   - A commit: `mkdir -p .run && { git show --format= --name-status <sha>; echo; git show --format= <sha>; } > .run/verify-jev.diff; wc -c .run/verify-jev.diff`
   - A range: the same with `git diff --name-status <range>` and `git diff <range>`.

   If the file is empty there is nothing to verify; say so and stop. Over 80,000 bytes it won't fit one Jev call (code diffs run about 3 bytes per token): rewrite it with the name-status list and the `--stat` of the same `git show` or `git diff` instead of the full diff.
